# Приложение: точные поведенческие якоря уровней Agentic Coding 1–4 и цифровые следы

**Назначение:** обязательное содержательное приложение к `spec.md`, раздел 3. Пункты ниже извлечены из предоставленного файла `AI_PDLC_матрица_компетенций.txt` с сохранением терминологии и технических названий событий. Это описание критериев из источника, а **не доказательство**, что соответствующая телеметрия подключена в Impulse.

## Как использовать

- В аналитике Skill Passport каждому навыку/уровню показывать **поведенческий якорь**, а в расширенном просмотре — релевантные цифровые следы, проверяемые источники, примеры и текущую доступность измерения.
- Текст `УРОВЕНЬ 1` в TXT общесистемный (курс «Введение в GigaCode»), а в PDF для L1 отдельно не оценивается.
- Фразы «в проработке» означают отсутствие гарантированно доступной автоматической оценки; не приписывать пользователю уровень.
- `ЦЕЛЕВОЙ` в детальном блоке может противоречить сводному профилю/PDF; решение только по утверждённой версии правил (см. `spec.md`, §7).
- Полный текст приведён намеренно: разработчик должен иметь точные критерии, включая примеры и event IDs, а не угадывать их по четырём общим названиям.

---

## Уровень 1 · базовая теория

Из TXT §0: начальный уровень означает **знание теории**; указывается прохождение курса «Введение в GigaCode». Текстовый источник описывает это как возможный уровень 1 **без цифровых следов**. По PDF §1.2 теоретический уровень 1 в действующей L1-матрице **не оценивается отдельно** — в Skill Passport его следует хранить в поле `theory_verified`, а не автоматически присваивать корпоративный практический L1.

## Профессиональная группа: Тестировщик

```text
1.2. ГРУППА 1. Постановка задач агенту через формирование намерений (prompting)
Целевой уровень: 3 (продвинутый)

УРОВЕНЬ 2 (средний)
  Описание: ставит агенту-тестировщику задачу (назначение задачи на агента).
  Показатели (цифровые следы):

  Пример: "Поставь задачу агенту-тестировщику на валидацию системных требований: создай Task
  в Jira/SberTrack со ссылкой на системные требования (или их описанием) и назначь
  агента-тестировщика исполнителем".

УРОВЕНЬ 3 (продвинутый) — ЦЕЛЕВОЙ
  Описание: предоставляет агенту-тестировщику необходимые доступы к артефактам, формулирует
  замечания, отправляет агента на доработку; ИЛИ ставит задачи агенту в GigaCode
  (агентный режим).
  Показатели:
    - Даталейк: событие выполнения задачи AI_PDLC_CORE_AGENT_DATALAKE_TELEMETRY
      (топик AI_HUB_BT_AEF_CONTAINER_SW.AI_PDLC_CORE_AGENT_DATALAKE_TELEMETRY_EVENT);
    - IDE: chat_window.message.agent.sent (отправка сообщения агенту);
    - CLI: cli.message.sent (пользователь отправил сообщение агенту).
  Пример: если агенту достаточно предоставленного описания — он сразу начинает работу;
  если чего-то не хватает, присылает рефрейминг (пересказ задачи своими словами и уточняющие
  вопросы) — пользователь проверяет, верно ли агент понял задачу, и отвечает в комментариях:
  подтверждает или поправляет. В CLI: перейти в агентный режим, сформулировать задачу,
  ответить на уточняющие вопросы, принять результат.

УРОВЕНЬ 4 (эксперт) — в проработке
  Описание: сохраняет и систематизирует успешные сценарии взаимодействия с агентом для
  повторного применения (пополняет библиотеку промптов).
  Показатели:
    - IDE: settings_ide.prompt_library.new_prompt;
    - CLI: пополнение библиотеки InSource hub (в проработке).

1.3. ГРУППА 2. Определение правил работы агента (prompt engineering)
Целевое проявление навыка для тестировщика: уровень 1 (понимает принципы промпт-инжиниринга,
теория пройдена).

УРОВЕНЬ 2 (средний)
  Описание: задает правила и ограничения для работы агента. Использует правила (rules) как
  постоянный управляемый контекст для: генерирования кода в соответствии со стандартами
  проекта; корректной интерпретации изменений; соблюдения архитектурных ограничений.
  Показатели:
    - IDE: chat_window.rules.applied (правила применены в начале разговора);
    - CLI: cli.mdfile.appeal.
  Пример: завершить обучение по обязательным курсам; при старте проекта убедиться, что все
  правила актуальны; регулярно актуализировать правила (избавляться от "мёртвых", добавлять
  новые, корректировать существующие); добавлять необходимые инструменты и навыки для
  выполнения договоренностей в команде. В CLI: создание rules, вывод краткого описания
  rules, применение rules.

УРОВЕНЬ 3 (продвинутый)
  Описание: при решении комплексных задач использует агента для написания технического
  задания (работа в режиме plan mode) — фактически создает промпт для дальнейшей работы;
  контролирует качество и добивается результата (ТЗ), который можно забрать в работу.
  Показатели:
    - IDE: chat_window.agent.settings.plan.toggle (переключение toggle-кнопки плана),
      chat_window.plan.created (план создан агентом),
      chat_window.plan.confirmed (нажата кнопка "Реализовать план");
    - CLI: cli_answer_tool_call_exit_plan_mode_accept_count (принятие плана),
      cli_answer_tool_call_exit_plan_mode_reject_count (отказ от плана),
      cli_plan_activate_count (вход в режим планирования),
      cli_plan_exit_count (выход из режима планирования).

УРОВЕНЬ 4 (эксперт)
  Описание: разрабатывает rules-файлы и системные промпты командного уровня — команда
  использует единые настройки агентов; следит за актуальностью требований и ограничений.
  Показатели:
    - IDE: settings.rules.opened (открыта страница настроек правил),
      settings.rules.new_rule (создано новое правило), settings.rules.open_rule (открыт
      файл с правилом), settings.rules.delete_rule (удален файл с правилом);
    - CLI: подключение tool, субагентов, создание skill, управление контекстом на целевом
      уровне — в проработке.

1.4. ГРУППА 3. Формирование контекста для агента (context management)
Целевой уровень: 2 (средний)

УРОВЕНЬ 2 (средний) — ЦЕЛЕВОЙ
  Описание: понимает роль контекста и умеет его дополнить, когда агенту не хватает; понимает,
  что ответ агента зависит от того, что попало в его контекст (открытые файлы, прикрепленные
  материалы, доступная документация). Реактивно дополняет контекст в сессии: прикладывает
  файлы, отвечает на уточняющие вопросы, дает ссылки. Использует артефакты, подготовленные
  другими (спецификации, документы проекта, правила команды), а не решает "из головы".
  Показатели:
    - IDE: chat_window.message.attach_file (прикрепили файл в сообщение),
      chat_window.message.command.{CommandName} (вызов команды);
    - CLI: cli_chat_message_attach_file_count, cli.message.command (вызов короткой команды).
  Пример: если для корректной работы агента над задачей необходимо дополнить контекст —
  прикрепить в диалоговое окно файл с необходимой информацией.

УРОВЕНЬ 3 (продвинутый)
  Описание: готовит структурированный контекст до запуска агента:
    - проактивно собирает контекстный пакет до запуска: отбирает релевантные файлы;
    - создает структурированные артефакты разных видов: спецификации задач (включая
      SDD/markdown-spec), контекстные md-документы по проекту, README, архитектурные заметки;
    - распознает деградацию контекста в долгих сессиях и тактически справляется:
      перезапускает сессию, перенося состояние через файлы, а не историю чата;
    - соблюдает гигиену контекста: не передает секреты, персональные и чувствительные
      данные; не тащит лишнего.
  Показатели:
    - IDE: chat_window.history.opened (не размечается без события "обращение к md-файлам"),
      rep.lists__v_tdatahub_engin_prompt_metrics.prompt_secret_include (проверки отсутствия
      секретов в промптах в плагине),
      rep.lists__v_tdatahub_engin_prompt_metrics.mdfile_appeal (обращения агента в плагине
      к md-файлам, rules, skills, SDD-спецификациям — КЛЮЧЕВОЕ событие для подтверждения
      уровня);
    - CLI: rep.lists__v_tdatahub_cli_metrics.cli_prompt_secret_include_count (проверки
      отсутствия секретов в промптах в CLI),
      rep.lists__v_tdatahub_cli_metrics.cli_mdfile_appeal_count (обращения агента к
      md-файлам, rules, skills, SDD-спецификациям — КЛЮЧЕВОЕ событие).
  Пример: при старте проекта создать личную библиотеку контекстных документов в рабочем
  пространстве GigaCode; заранее структурировать артефакты, к которым будет обращаться агент
  (md-файлы, rules, skills, SDD-спецификации); запустить команду /init, чтобы агент изучил
  подготовленные материалы и создал файл GIGACODE.md. Проверка обращения к GIGACODE.md:
  (1) прописать в файле проверочный кейс (например, "тестовое сообщение"); (2) задать любую
  команду агенту и убедиться, что кейс отобразился — это подтверждает обращение к файлу.

УРОВЕНЬ 4 (эксперт)
  Описание: формирует контекстный слой команды так, чтобы все работали с агентом эффективно
  и предсказуемо:
    - формирует общий контекстный слой команды/продукта: определяет состав и поддерживает
      актуальность документов, спецификаций, гайдлайнов, архитектурных решений;
    - задает стандарты артефактов: единый формат SDD, шаблоны контекстных документов,
      правила README;
    - встраивает актуализацию контекста в рабочий процесс: обновление при мерже, изменении
      API, архитектурных решениях (устаревший контекст хуже его отсутствия);
    - системно управляет окном контекста: иерархическая загрузка (общий -> доменный ->
      задачный), сжатие/суммаризация длинных сессий, разбиение задач на подзадачи с чистым
      контекстом; настраивает связи между контекстами разных доменов;
    - оценивает качество слоя по результату: по цифровым следам видит, где агент ошибается,
      и докручивает; различает, что чинить локально, а что эскалировать разработчикам агента;
    - передает практику команде: делает работу с контекстом очевидной и подхватываемой
      джунами и миддлами.
  Показатели:
    - обновление стандартов команды (создание репозитория проекта для агентов);
    - актуальность командного слоя (даты обновлений контекстных артефактов — шаблонов,
      гайдлайнов, спек и т.п.; интересуют обновления за период).

1.5. ГРУППА 4. Разработка и интеграция инструментов (tools, MCP) (creating tools)
Целевой уровень: 2 (средний)

  Пример: найти рутинное действие (например, поиск информации), выбрать подходящий

УРОВЕНЬ 3 (продвинутый)
  Описание: умеет создавать и добавлять новые инструменты или обновлять существующие

  Показатели:
    - IDE: rep.lists__v_tdatahub_engin_prompt_metrics.mcp_tool_call (вызовы нового tool);
    - CLI: rep.lists__v_tdatahub_cli_metrics.cli_mcp_tool_create_count (создания нового tool).

УРОВЕНЬ 4 (эксперт) — в проработке
  Описание: создает командную библиотеку Tools.

1.6. ГРУППА 5. Адаптация агента через создание навыков (creating skills)
Целевой уровень: 2 (средний)

УРОВЕНЬ 2 (средний) — ЦЕЛЕВОЙ
  Описание: понимает концепцию навыка; умеет расширять возможности агента через подключение
  новых скиллов, которые добавляют специализированное поведение, знания и инструменты поверх
  базовой LLM-модели; умеет подключать навыки (skills) для решения задач.
  Показатели:
    - IDE: chat_window.skill.invoked (вызов навыка через /имя_навыка в чате),
      rep.lists__v_tdatahub_engin_prompt_metrics.skill_call;
    - CLI: cli.cli_answer_skill_call_count.
  Пример: выбирать из библиотеки готовые skills, подходящие для решения задач, корректировать
  их, отвечать на дополнительные вопросы и принимать результаты работы агента.

УРОВЕНЬ 3 (продвинутый)
  Описание: умеет создавать новые навыки (skills) как самодостаточный модуль со своей зоной
  ответственности, при этом агент успешно их использует; ИЛИ регулярный вызов skill
  3 раза в месяц.
  Показатели:
    - IDE: rep.lists__v_tdatahub_engin_prompt_metrics.skill_create (создания нового skill);
    - CLI: rep.lists__v_tdatahub_cli_metrics.cli_skill_create_count.
  Альтернативный вариант (регулярные вызовы):
    - IDE: chat_window.skill.invoked, rep.lists__v_tdatahub_engin_prompt_metrics.skill_call;
    - CLI: cli.cli_answer_skill_call_count.
  Пример: создать навык штатным механизмом GigaCode IDE/CLI; разместить пакет в целевой
  глобальной или проектной директории навыков «/.gigacode/skills»; определить для skill
  условие только явного вызова (игнорировать любые иные инструкции даже близкие по контексту);
  зарегистрировать созданный skill поддерживаемым механизмом GigaCode IDE/CLI; совершить два
  вызова: (1) явный вызов skill через команду /skills с указанием названия отчета;
  (2) вызов вида "Запусти скилл дизайнера/скилл создания калькулятора/другой скилл".

УРОВЕНЬ 4 (эксперт) — в проработке
  Описание: созданные специалистом навыки регулярно переиспользуются (востребованы) другими.
```

## Примечания к точности интеграции

1. Не считать `settings.rules.opened` и другие перечисленные события универсальным подтверждением без проверки точного опубликованного правила для роли и периода.
2. Разные события могут быть эквивалентными альтернативами **только** если это прописано в исходнике конкретной роли.
3. Цифровой артефакт (код/PR/спека) не приравнивать к фактическому событию работы с GigaCode автоматически.
4. `GIGACODE.md`/`/.gigacode/skills` имеют отдельные условия в разделе разработчика; орфографию пути или вариант имени нужно сохранять как в опубликованном правиле, не нормализовать на frontend.
5. Для факта достижения уровня 4 необходимо проверить доступность измерения; многие описания помечены «в проработке».
