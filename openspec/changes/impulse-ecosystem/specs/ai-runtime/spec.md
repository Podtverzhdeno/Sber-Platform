# Spec Delta

## Purpose

Определяет безопасное серверное выполнение AI, выбор подходящей модели, изоляцию бесед, контролируемый fallback и сохранение ручного пути при сбоях.

## ADDED Requirements

### Requirement: Серверный модельный шлюз
Python backend SHALL отправлять запросы к OpenRouter только через ModelGateway, SHALL держать ключ вне клиента и SHALL передавать цель вызова и версию политики.

#### Scenario: Запрос Buddy
- **WHEN** участник отправляет сообщение Buddy
- **THEN** сервер проверяет сессию, выбирает модель для назначения Buddy и не возвращает ключ в API или trace

#### Scenario: Нет ключа в среде
- **WHEN** AI включён, а серверный ключ не настроен
- **THEN** агент не запускается и возвращает контролируемый `MODEL_UNAVAILABLE`, а основной интерфейс остаётся доступен

### Requirement: Выбор модели по возможностям
ModelGateway SHALL проверять доступность утверждённого endpoint и обязательные возможности tool calling или structured output до запуска и SHALL валидировать результат серверной схемой.

#### Scenario: Endpoint без JSON Schema
- **WHEN** для черновика ревью выбран endpoint без требуемого structured output
- **THEN** запрос не отправляется на этот endpoint, выбирается только разрешённый fallback либо ручной процесс

### Requirement: Приватность маршрутизации
ModelGateway SHALL блокировать передачу класса данных без утверждённой политики провайдера, региона и retention и SHALL не смягчать её при fallback.

#### Scenario: Закрытый R&D-бриф
- **WHEN** помощник заказчика получает внутренний бриф, запрещённый для внешнего inference
- **THEN** OpenRouter не вызывается, заказчику предлагается ручной шаблон, а событие блокировки записано

### Requirement: Раздельные ограничения
Каждый вид агента SHALL иметь собственные ограничения времени, вызовов инструментов, токенов, параллелизма и частоты запросов с явным завершением при исчерпании.

#### Scenario: Цикл вызовов
- **WHEN** модель повторно вызывает один инструмент сверх лимита
- **THEN** граф останавливается без записи доменных изменений и сообщает о неполном ответе

### Requirement: Контролируемый fallback
Fallback SHALL использовать только модели и endpoints из той же или более строгой политики данных и с необходимыми возможностями; фактический провайдер SHALL фиксироваться в run.

#### Scenario: Ошибка провайдера
- **WHEN** primary model возвращает временную ошибку
- **THEN** разрешённый fallback запускается не более установленного политикой числа раз, а его ID и причина видны оператору

### Requirement: Сохранение и восстановление графа
LangGraph SHALL сохранять состояние по связанному с человеком thread и SHALL восстанавливать ожидающий человеческого решения run после рестарта.

#### Scenario: Рестарт во время approval
- **WHEN** процесс перезапущен после создания черновика ревью
- **THEN** ментор видит ровно одно предложение и может принять решение один раз

### Requirement: Отключение AI
Оператор SHALL независимо выключать каждый тип агента feature flag, а обычные действия платформы SHALL продолжать работать.

#### Scenario: OpenRouter недоступен
- **WHEN** все допустимые модели недоступны
- **THEN** участник видит штатный roadmap и задачи, а ментор проверяет вклад вручную

### Requirement: Схема ответов
Платформа SHALL валидировать AI output типизированной серверной схемой и SHALL не применять неверный payload к доменным объектам.

#### Scenario: Неверный JSON
- **WHEN** модель возвращает невалидный черновик ревью
- **THEN** доменная оценка не меняется, run помечается ошибкой, а ментор получает ручную форму
