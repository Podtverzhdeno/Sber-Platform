# Information Architecture — шесть ролей Impulse Calm

## Общая модель

Общий shell: Главная (если разрешена) → 3–5 тематических групп → сервисные действия в header или account menu. Группы содержат существующие серверные destinations, а не новые URL. Названия групп могут различаться по ролям, но глубина sidebar строго <=2: группа → экран. Третий уровень — внутренние вкладки/фильтры конкретного экрана. Пункт, отсутствующий в actor.navigation, не показывается даже при сохранённом выборе или открытом URL. В неизвестной роли/версии пункты не теряются: их показывает нейтральная группа «Другие разделы» при наличии соответствующего server-permitted label.

Общие действия: поиск, уведомления, личный профиль/смена роли при наличии разрешения и справка. Они не дублируют sidebar. Настройки доступны через профиль, но при наличии серверного destination «Настройки» также допустим доступ из utility-group, что сохраняет обратную совместимость. Состояние открытых групп может запоминаться локально; оно никогда не является ACL.

## Участник

| Меню → подраздел | L0: всегда видно | L1 по выбору | L2 и ограничения |
|---|---|---|---|
| Главная | персональный следующий шаг, текущая роль/направление, важная незавершённая задача | компактный список «Сегодня», недавняя активность и основание прогресса | все метрики по клику; никаких фальшивых чисел |
| Развитие → Мой путь / Моя траектория | основная роль, текущий Impulse level/статус, один следующий уровень | карты основного и дополнительных направлений, необходимые курсы, прогресс этапов | заморозка/возврат направления, история, детали требований; не стирать подтверждённое |
| Развитие → Bootcamp | продолжить текущий курс, подтверждённый прогресс, актуальная цель | каталог, фильтры, темы, уроки, тесты, доп.курсы | сертификаты, история; отдельно «пройдено»/«подтверждено» |
| Практика → Задачи | подходящая задача и доступный отклик, deadline/условия | каталог/список, фильтры, мои отклики, детали | рубрика, условия paid/unpaid, дедлайны, доказательства; не скрывать важные ограничения |
| Практика → Мои проекты | текущий проект + ближайший checkpoint | команда, вклад, прогресс, документы, этапы | история загрузок, критерии и проверка, журнал событий; никакой потери файлов |
| Результаты → Портфолио | подтверждённые кейсы и Skill Passport | проекты, навыки, документы, публичность | evidence provenance, версии, настройки видимости |
| Результаты → Аналитика | короткий фактический обзор изменений | активность GitHub-style, навыки, сертификаты, фильтры дат | расшифровка каждого показателя, источник, пустой статус |
| Результаты → Достижения | недавно подтверждённое достижение | коллекции, фильтры, статусы | условия/ревокации и внешнее подтверждение |
| Результаты → Рейтинг | личная позиция если доступна | сезон, участники и условия подсчёта | баллы, ledger, privacy и объяснение, что рейтинг не решение о найме |
| Сообщество → События | ближайшие подходящие события | каталог, фильтры, избранное | детали участия и статус доказательства |
| Сообщество → Сообщения | непрочитанное и последний релевантный диалог | список чатов, поиск и вложения | параметры каналов, история; не разглашать чужие сообщения |
| Помощь → AI-Buddy | спокойная подсказка «спросить об этом разделе» | контекстные предложения, чат по согласию | источники, AI unavailable, настройки памяти и privacy |
| Аккаунт → Настройки | профиль и самые важные опции | видимость, уведомления, тема | безопасность, согласия, удаление/retention с явным подтверждением |

В глобальном меню L0 допустимы лишь «Главная», «Развитие», «Практика», «Результаты», «Сообщество» (+ компактный AI Buddy если разрешён). Профиль и настройки — в account menu. Не более одного auto-open group: группа текущего экрана. Кнопка «Продолжить» ведёт к конкретному уроку/задаче, а не в пустой каталог.

## Заказчик

| Меню → подраздел | L0 | L1 | L2 и ограничения |
|---|---|---|---|
| Главная | задачи, ожидающие решения; один primary «Создать задачу» или «Проверить результат» | мои активные заявки/чекпойнты | аналитика без дублирования карточек |
| Задачи → Мои задачи / Задачи | рабочий статус и дедлайн, очередь задач | черновики, опубликованные, в работе, завершённые | условия версии, команда, история |
| Задачи → Создать задачу | понятная пошаговая форма с одной следующей кнопкой | дополнительные параметры по секциям | согласия/деньги/модерация видимы перед публикацией |
| Задачи → Заявки | новые отклики с точными основаниями | фильтр, short list, переписка | не смешивать приглашённых и открытые заявки |
| Люди → Кандидаты / База участников / Участники | поиск только consented кандидатов | специализация, кейсы, совпадения | доказательства доступности и версии согласия |
| Работа → Назначения / Результаты | ближайший checkpoint, требующие решения результаты | вклад, команда, комментарии | формальная приёмка, рубрики, аудит |
| Работа → Аналитика | полезные показатели задачи/воронки | периоды, разрезы, сравнения | определения метрик и источники |
| Коммуникация → Сообщения | непрочитанные/связанные с задачей | участники, вложения | RBAC; не раскрывать закрытое |
| Помощь → AI-помощник | контекстное предложение | бриф/черновик | ни одно consequential действие не выполняется моделью |
| Аккаунт → Настройки | профиль, уведомления | параметры | доступ, согласия, аудит |

Если активный workflow создания задачи, скрыть не относящиеся к этапу настройки под «Дополнительные параметры», но черновик и обязательные поля оставлять видимыми.

## Mapping алгоритм L0 и fallback

- Группа получает только элементы, которые реально присутствуют в текущем navigation массива; порядок внутри группы сохраняет серверный порядок.
- Если группам не принадлежат неизвестные метки, все неизвестные попадают в «Другие разделы». Списки групп не заставляют показать запрещённые названия.
- Навигация содержит индекс оригинального массива, а не индекс внутри группы.
- При ошибке загрузки actor/menu показывать старое безопасное состояние загрузки и повтор, а не демо-пользователей.
- При отсутствии currentSection показывать 404/Restricted state, не подставляя произвольную роль.
- «Создать задачу» может быть primary CTA только если сервер реально разрешил destination.
- AI-Buddy не отображается при отсутствии прав/флагов.
- Ранжирование по частоте посещений — возможный будущий opt-in, но оно не изменяет backend permissions или идентичность маршрута.

## Порядок migration и критерий готовности каждой области

1. Navigation shell: все существующие разрешённые пути достижимы; active / Back / Forward / keyboard; mobile drawer.
2. Home всех ролей: один next action, персональный фокус и честные состояния.
3. Обучение: курс/урок/практика/сертификат; прогресс не теряется.
4. Практика: подбор/отклик/вклад/checkpoint/результат; разрешения и версионирование.
5. Проверяемый опыт: Skill Passport/портфолио/достижения/рейтинг; прозрачное основание.
6. Коммуникации: личные/групповые чаты, вложения, изоляция.
7. Аналитика: компактная сводка + drill-down; не подменять реальные данные.
8. Настройки и AI: consent, flags, memory/privacy, degraded state.
9. Отдельные role-specific операции: подтверждение заказчиком, ревью ментором, подбор руководителем/HR, проверка оператором.

Для каждого пункта сохранить тест: old route reachability, current API response, 320/390/768/1024/1440 viewport, mouse, touch, keyboard, light/dark, no-data, error, RBAC negative. Это roadmap, а не утверждение, что вся реализация уже выполнена.
