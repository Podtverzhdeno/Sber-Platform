# Capability: calm-navigation

## ADDED Requirements

### Requirement: Содержание меню строго соответствует серверной роли
Навигация SHALL строиться исключительно из разрешённых backend actor.navigation destinations. Группы MAY отражать пользовательские сценарии, но SHALL NOT добавлять неразрешённые маршруты, менять индекс текущего destination или подменять его известной меткой. Непредвиденные разрешённые пункты SHALL оставаться доступными в группе «Другие разделы».

#### Scenario: Участнику не назначены чужие экраны
- **WHEN** текущий actor.navigation не содержит «Проверки» или «Создать задачу»
- **THEN** ни раскрытие меню, ни поиск в меню, ни выбранная пользовательская группа не показывают эти пункты

#### Scenario: Неизвестный backend label
- **WHEN** backend передал разрешённый label, которого нет в таблице группировки
- **THEN** пункт доступен в «Другие разделы» и ведёт на свой исходный /workspace/:index без ошибки

### Requirement: Двухуровневая информационная иерархия
Sidebar SHALL показывать не более шести top-level групп/пунктов с понятными метками; подгруппы SHALL раскрываться только по нажатию/клавиатуре, не глубже двух уровней. Активная группа SHALL быть раскрыта после прямого deep-link, Back или смены экранного маршрута.

#### Scenario: Первый вход
- **WHEN** участник открывает главную страницу
- **THEN** показаны только компактные группы и «Главная»; длинный список курсов, проектов, аналитики и настроек не занимает экран

#### Scenario: Открытие подраздела
- **WHEN** пользователь активирует «Развитие» клавишей Enter/Space
- **THEN** раскрываются только разрешённые подпункты группы, состояние отражено aria-expanded и focus остаётся предсказуемым

#### Scenario: Активная страница скрытой группы
- **WHEN** пользователь открывает старый URL /workspace/3 из закладок
- **THEN** выделен именно исходный пункт с индексом 3 и его группа раскрыта

### Requirement: Сохранение адресации и обратной совместимости
Каждый navigation destination SHALL использовать исходный индекс actor.navigation, а не индекс внутри отфильтрованной группы. Browser Back/Forward, глобальный поиск, server redirects и прямые ссылки SHALL продолжать работать.

#### Scenario: Группировка меняет порядок UI
- **WHEN** группа «Практика» отображает элементы из разных позиций исходного массива
- **THEN** каждый link содержит исходный индекс и открывает исходный экран

#### Scenario: History navigation
- **WHEN** пользователь открывает пункт, нажимает Back и Forward
- **THEN** текущий пункт, раскрытая группа и контент синхронизируются с URL без лишней навигации

### Requirement: Смена роли не расширяет полномочия
После успешной смены рабочей роли sidebar SHALL перестроиться только из нового ответа API; недоступные предыдущие пункты SHALL скрыться. Клиентское сохранение opened-state SHALL NOT быть основанием для доступа.

#### Scenario: Переход участник → заказчик
- **WHEN** backend назначил другую активную роль и новый navigation array
- **THEN** отображаются только новые разрешённые пункты; старые участнические пути не становятся доступными из меню

### Requirement: Mobile drawer доступен и не препятствует взаимодействию
При узкой ширине sidebar SHALL открываться из явной кнопки с aria-expanded, иметь понятное имя, закрываться Escape и выбором ссылки и возвращать keyboard focus на вызвавшую кнопку. При закрытом меню пункты SHALL NOT попадать в порядок Tab.

#### Scenario: Открытие и закрытие с клавиатуры
- **WHEN** пользователь активирует «Меню», затем Escape
- **THEN** drawer закрывается, фокус возвращается к «Меню» и основной экран снова доступен

#### Scenario: Узкий экран
- **WHEN** viewport 320px, 390px или 768px
- **THEN** отсутствует горизонтальный скролл из-за боковой панели, touch targets не меньше 44×44 CSS px, содержимое не обрезается

### Requirement: Отсутствие навязчивого промо и ложных бейджей
Sidebar SHALL содержать только navigation и уместные utility controls. Декоративные блоки и количественные бейджи без действительных свежих данных SHALL NOT показываться.

#### Scenario: Нет уведомлений/контекстных цифр
- **WHEN** API не предоставил актуальный unread count
- **THEN** меню не рисует фиктивный счётчик или «важность» для привлечения внимания

### Requirement: Состояния компонента наблюдаемы и проверяемы
Разработка SHALL включать unit/component tests для grouping, fallback, role switch, активной ссылки, клавиатуры и Mobile. Интеграционная приёмка SHALL выполнять E2E на реальном backend для шести ролей и отрицательные проверки RBAC.

#### Scenario: Реализация прошла только unit tests
- **WHEN** не выполнены общий Playwright, Android/iOS touch smoke или manual 6-role review на интеграционном SHA
- **THEN** change status SHALL оставаться REVIEW, не DONE или PROD READY
