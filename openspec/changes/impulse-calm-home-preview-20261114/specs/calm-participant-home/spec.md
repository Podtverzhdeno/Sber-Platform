# Capability: calm-participant-home

## ADDED Requirements

### Requirement: Только согласованная главная участника
При параметре `home=calm` главная участника SHALL показывать новую композицию в отдельной CSS области. Без параметра UI SHALL сохранять прежний экран; другие роли, URL, роли, API и навигация SHALL NOT меняться.

#### Scenario: Предпросмотр
- **WHEN** участник открывает `/workspace/0?home=calm`
- **THEN** видна спокойная версия главной с одной основной кнопкой и сокращённым обзором

#### Scenario: Старый интерфейс без флага
- **WHEN** пользователь открывает `/workspace/0`
- **THEN** рендерится прежний ParticipantHomeV2Body без изменений в маршрутах или данных

### Requirement: Одно реальное приоритетное действие
Главная SHALL определять главную задачу из разрешённого overview: активная работа, если доступна и требует действия, затем `next_outcome`, иначе переход к траектории. Она SHALL NOT обещать завершение, повышать уровень или создавать фиктивный прогресс.

#### Scenario: Задача ожидает действия
- **WHEN** среди active_tasks есть задача с действием, отличным от `await_review`
- **THEN** основной CTA ведёт к её canonical `task_id`

#### Scenario: Нет задачи
- **WHEN** active_tasks пусты, но есть `next_outcome` типа `course`
- **THEN** кнопка ведёт к реальному `course` ключу

#### Scenario: Нет next outcome
- **WHEN** ни задачи, ни next outcome нет
- **THEN** предлагается открыть свою траекторию, а не создаются пустые задания

### Requirement: Обзор не подменяет статусы
Impulse level, активные задачи, проверенные практические навыки и недельный фокус SHALL показывать значения только из API. При ошибке или неизвестном уровне SHALL показываться понятное «Данные недоступны», а не ноль. Career grade SHALL NOT отображаться как Impulse level.

#### Scenario: Уровень недоступен
- **WHEN** запрос Impulse level вернул ошибку
- **THEN** уровень «—» и объяснение, без выдуманного L0

#### Scenario: Навыки недоступны
- **WHEN** API skill passport отказал
- **THEN** главная не показывает выдуманное число подтверждений и сохраняет доступ к портфолио

### Requirement: Инструменты раскрываются осознанно
Требования нового уровня, перечень курсов, практика и детали недельного плана SHALL находиться в логических блоках, не конкурирующих с главным действием. Запрос курса/прогресса SHALL включаться только при раскрытии требований.

#### Scenario: Пользователь открывает требования
- **WHEN** пользователь нажимает «Требования уровня»
- **THEN** видны действительные обязательные курсы, их статусы и переходы «Пройти» при наличии опубликованного curriculum

#### Scenario: Нет опубликованной программы
- **WHEN** curriculum_state равен `unpublished`
- **THEN** показано честное уведомление о недоступности программы и нет фиктивных кнопок перехода

### Requirement: Доступность и качество
Новая главная SHALL быть доступна на 320/390/768/1024/1440px, поддерживать клавиатуру, скринридер, светлую/тёмную тему и `prefers-reduced-motion`. Остальные экраны и старые визуальные тесты SHALL сохранять прежний CSS. Изолированные unit/component тесты SHALL проверять критичные состояния.

#### Scenario: Keyboard-only
- **WHEN** пользователь взаимодействует с главным действием, неделей и требованиями уровня с клавиатуры
- **THEN** элементы доступны по Tab/Enter/Space, имеют видимый фокус и объявляемые подписи

#### Scenario: Regression
- **WHEN** активирована старая версия страницы или открыт любой другой раздел
- **THEN** новые CSS правила не влияют на его элементы
