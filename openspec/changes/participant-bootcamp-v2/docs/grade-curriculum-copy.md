# Approved Bootcamp grade and curriculum copy

## Decision

Этот документ закрывает `BC2-002` и является обязательным copy-contract для Bootcamp. Он не утверждает названия или количество карьерных грейдов: они приходят только из опубликованного grade catalog.

Основное правило:

- отдельный курс закрывает только соответствующее требование curriculum;
- material progress, `reported` completion и expected skill impact не повышают readiness как verified evidence;
- после проверки всех требований и достижения readiness `100%` сервер автоматически, атомарно и идемпотентно выполняет следующий разрешённый policy переход без human confirmation;
- клиент не назначает grade и не показывает переход до получения обновлённой server projection;
- при отсутствии active published policy grade остаётся `provisional/not_evaluable`, автоматический переход выключен.

## Required UI copy by state

| State | Heading | Supporting copy | Allowed CTA |

| Остались только courses | `Осталось курсов: {remaining_course_count}` | `После проверки последнего курса платформа пересчитает готовность. При 100% следующий разрешённый грейд присваивается автоматически.` | `Посмотреть курсы` |
| Courses завершены, осталась практика/evidence | `Учебная часть завершена` | `Чтобы завершить переход, закройте оставшиеся практические требования и дождитесь проверки evidence.` | Переход к первому разрешённому requirement |
| Последнее evidence отправлено, но не проверено | `Ожидаем проверку последнего результата` | `Отправленный результат ещё не считается подтверждённым. После проверки платформа пересчитает готовность автоматически.` | `Открыть отправленный результат` |
| Readiness 100%, transition выполняется | `Все требования подтверждены` | `Платформа автоматически оформляет следующий разрешённый грейд. Обновлять или отправлять данные повторно не нужно.` | Только безопасное `Обновить статус`, если projection stale |
| Transition завершён | `Новый грейд присвоен автоматически` | `Переход подтверждён системой по политике {policy_version} · расчёт на {as_of}.` | `Открыть историю грейда` |

| Grade/readiness unknown из-за недоступного источника | `Статус грейда временно недоступен` | `Учебный прогресс сохранён. Мы не подставляем приблизительный процент; попробуйте обновить данные позже.` | `Обновить` |
| Evidence revoked после перехода | `Часть подтверждений требует пересмотра` | `История присвоенного грейда сохранена. Текущая проекция помечена как требующая пересчёта по действующей recovery policy.` | `Посмотреть затронутые требования` |

## Course-level copy

### «Надо пройти»

`Этот курс закрывает требование «{requirement_title}» программы {curriculum_version}. После прохождения потребуется {verification_step}. Сам по себе курс не присваивает новый грейд.`

### Expected competency impact

`Ожидаемый результат: «{competency}» — с {current_or_unknown} до {projected}. Цель траектории — {target}. Прогноз станет подтверждённым уровнем только после {required_evidence_or_checkpoint}.`

### Reported completion

`Завершение отправлено на проверку. Оно ещё не повышает подтверждённую готовность или уровень навыка.`

### Verified completion, policy still incomplete

`Курс подтверждён и учтён в готовности. До автоматического перехода остаются другие требования программы.`

### Locked course

`Сначала подтвердите «{prerequisite_title}». После обновления статуса доступ будет пересчитан автоматически.`

## Requirements drawer copy rules

1. Заголовок использует server values `current_grade.title` и `target_grade.title` только при published policy; UI не собирает `Грейд N → Грейд N+1` арифметикой.
2. `remaining_course_count` считается только по незавершённым course requirements выбранных `policy_version`/`curriculum_version`.
3. Course и non-course requirements показываются раздельно; нулевое число courses не означает readiness 100%.
4. `reported`, `rejected`, `revoked`, `stale` и `unknown` имеют текстовые labels и не считаются verified.
5. Формулировка `можно претендовать` запрещена: она ошибочно предполагает ручную заявку. Корректно — `платформа автоматически присвоит`, но только в условном тексте после проверки всех требований.
6. Формулировки `повышение гарантировано после курса`, `курс повысит грейд`, `получите грейд` и `осталось только посмотреть курс` запрещены.
7. Copy включает `policy_version` и `as_of` в details/provenance, но не перегружает ими primary heading.

## Role summary copy rules

- Current grade: `Текущий грейд: {server_title}`; если not evaluable — `Официальный грейд не рассчитан`.
- Readiness: `{readiness_percent}% готовности к {target_grade}` только при определённой versioned metric; рядом доступно `Как рассчитано`.
- Remaining: `Осталось {remaining_percent}%` является комплементарным тому же серверному расчёту, а не отдельной frontend формулой.
- `Грейд`, skill level, stage progress, XP/rating и review grade A/B/C никогда не называются взаимозаменяемыми.

## Accessibility and localization

- Числа и статусы дублируются текстом; цвет/анимация не являются единственным объяснением.
- Автоматический переход может сопровождаться reduced-motion-safe celebration, но status announcement использует `aria-live=polite` и остаётся понятным без анимации.
- Склонение `курс/курса/курсов` выполняется formatter, а не строковой конкатенацией.
- Названия policy/grade/requirements приходят как данные и экранируются; UI не хардкодит семь уровней прототипа.

## Acceptance examples

| Input facts | Correct output | Forbidden output |
|---|---|---|
| 2 course requirements open, readiness 64% | `Осталось курсов: 2`; объяснение всех требований | `Пройдите 2 курса и получите новый грейд` |
| all courses verified, project open | `Учебная часть завершена`; перейти к проекту | `Все готово к повышению` |
| final evidence reported | ожидание проверки, no readiness credit | `Грейд скоро будет повышен` без оговорки о verification |
| readiness 100%, transition pending | автоматическое оформление, no repeat action | `Отправить заявку на повышение` |
| transition recorded | новый server grade, policy/as-of | client-calculated `N+1` |
| no policy | not evaluable + trajectory CTA | demo `Грейд 5`, `62%`, `осталось 2` |
