# Proposal — Архитектурная устойчивость и масштабируемость Impulse

## Why

Платформа быстро растёт: новые роли, Bootcamp, проекты, рейтинг, AI Buddy, аналитика и межраздельные проекции. В репозитории уже есть полезное разделение `domain / application / infrastructure / api`, типизированный React frontend и тесты, однако выборочный аудит 26 октября 2026 выявил нарушения направления зависимостей, крупные многоответственные модули и разрозненную логику cache invalidation. Без архитектурных ограничений новые сценарии будут увеличивать стоимость изменений и вероятность регрессий.

## What Changes

1. Провести воспроизводимый **полный аудит всех production source files**, включая Python, TypeScript/TSX, SCSS, интеграции, миграции, инфраструктуру и CI, с автоматической инвентаризацией и явной фиксацией непроверенных участков.
2. Утвердить целевую modular-monolith архитектуру: domain не зависит от web/SQL, application реализует use cases, infrastructure — adapters, API — transport и error mapping; composition root строит dependency graph.
3. Установить строгие, проверяемые границы frontend: feature modules, typed API adapters, query key ownership, scoped styles, route composition без бизнес-логики.
4. Обеспечить согласованность источников данных между курсами, траекторией, Skill Passport, задачами, рейтингом, AI Buddy и разными ролями без клиентского «изобретения» подтверждённых фактов.
5. Внедрять рефакторинг **малыми совместимыми PR**, с contract/integration/performance/role-security тестами, ADR и независимым ревью.
6. Добавить CI-проверки на запрещённые зависимости, циклы импортов, code growth, autogenerated boundary, регрессию контрактов и профиль качества.

## Explicit non-goals

- Не переводить MVP в микросервисы без доказанной потребности.
- Не переписывать приложение с нуля и не менять утверждённый UX/UI.
- Не изменять семантику verified evidence, грейдов, рейтинга, оплат или разрешений под предлогом рефакторинга.
- Не вводить произвольные ограничения размера исходников как единственный критерий архитектурного качества; generated files и декларативные fixtures оценивать отдельно.
- Не выполнять массовые изменения активных чужих scope, Railway deploy и изменения секретов.

## Success

Полный список файлов и зависимостей, risk-ranked register архитектурных проблем, C4/ADR, отсутствие неразрешённых dependency-direction violations, тестируемые и независимые модули, защищённые API/RBAC/transactions и зелёный architecture gate на точной интеграционной ревизии. Чекбоксы закрываются только независимым reviewer по свидетельствам, а не по факту подготовки этой спецификации.
