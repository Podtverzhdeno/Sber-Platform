# Аналитика участника: строгая проверка соответствия UI (2026-10-24)

## Вердикт
**1:1 НЕ ПОДТВЕРЖДЕНО.** Пройденный CI двух релизов и скриншоты текущей страницы не являются пиксельной проверкой по утверждённому исходному макету.

## Доступные входные материалы
- Семь скриншотов пользователя (`image(20261024-143011).png` … `image(20261024-143046).png`) — фактическое **предыдущее** состояние интерфейса до PR #32/#33, а НЕ целевые PNG.
- `openspec/changes/impulse-ecosystem/docs/analytics-agentic-coding/spec.md` — нормативные требования к матрице, сертификации и источникам.
- `openspec/changes/impulse-ecosystem/specs/analytics/spec.md` — UX/data requirements.
- `openspec/changes/impulse-ecosystem/docs/visual-reference-catalog.md` указывает Windows-путь `C:\\Users\\user\\Downloads\\Визуал\\Участник`, **не сохраняет PNG в репозиторий** и **не содержит отдельной записи Analytics** среди `R-PAR-01..12`. Следовательно, screenshot-тесты других страниц не являются сравнением с эталоном аналитики.
- Текущая production-ссылка требует выбора демо-персоны/авторизации. Авторизованный live screenshot в данном сеансе недоступен; состояние production после merge отдельно не подтверждено.
- Новые кандидаты снимков от Playwright записываются в CI report: `analytics-candidate-desktop-dark`, `analytics-candidate-mobile-dark`. **Это снимки реализации, не эталонные PNG**, и их нельзя утверждать автоматически.

## Конкретные условия закрытия
1. Поместить утверждённый макет аналитики участника и HTML/CSS из SDD в контролируемое расположение (или передать доступ к исходникам), зафиксировать версию, дату, масштаб и размеры viewport. **Не подменять его текущим Playwright screenshot.**
2. Получить воспроизводимые снимки реальной страницы после актуального deployment для 1440×900, 1024×768, 390×844, dark/light; desktop scroll/full-page, 3 роли × 3 вида диаграмм, technical/soft states, SkillDetail, CertificationDetail, loading/error/no-evidence.
3. Выполнить side-by-side и пиксельный diff с эталоном, измерить интервалы и ширины на ключевых блоках; каждое отличие либо исправить, либо согласовать с владельцем макета.
4. Ввести утверждённые PNG golden tests, отдельно от screenshot snapshot tests текущей реализации.
5. Завершить реальные срезы technical/soft, персонализированный план, остальные не демо показатели только при наличии авторитетных API.
6. Повторить auth-route live smoke. Только после этого помечать `visual_1_to_1=ACCEPTED`.
