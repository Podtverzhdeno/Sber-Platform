# Apple UI Kit — независимые проверки и реестр приёмки

Эта папка **намеренно находится вне \`Apple UI kit/**\`**: исходный каталог ещё принадлежит нескольким открытым задачам с состоянием REVIEW. Здесь только тестовые инструменты, которые читают уже имеющиеся референсы и не изменяют их. Встраивание в каталог, React, frontend E2E или CI — отдельная интеграционная задача после разрешения конфликтов и независимой приёмки.

## Шаг 1 — офлайн-проверка материалов

После получения репозитория на ветке, содержащей PR #184, #186, #189:

\`\`\`bash
node tools/apple-ui-kit-qa/verify-references.mjs
\`\`\`

**Не требует npm, пакетов или сетевых запросов.** Скрипт читает существующие файлы и проверяет структуру, техническую безопасность SVG и явные честные статусы \`pixel_verified=false\`. Результат: короткий PASS или детализация ошибок. Тест не утверждает, что графика точно повторяет Apple.

## Шаг 2 — настоящий браузерный smoke

В проекте уже имеется Playwright в devDependencies фронтенда. Установите штатные зависимости и браузер (только если отсутствуют):

\`\`\`bash
cd frontend
npm ci
npx playwright install chromium
cd ..
node tools/apple-ui-kit-qa/browser-smoke.mjs
\`\`\`

На Windows PowerShell выполняются те же команды из корня репозитория.

**Проверяемое поведение:**

1. Chromium открывает локальный \`Apple UI kit/fidelity-workbench/index.html\` без API и сервера.
2. Создаются синтетические PNG 2×2: одно отличие на 255 красного. Ожидаемые итоги: **1 отличающийся пиксель из 4 = 25,00%, средняя абсолютная RGB-ошибка = 21,25**.
3. Убедиться, что режим тепловой карты не исчезает после изменения порога, а JSON содержит численные метрики и \`verified_official_apple_source=false\`.
4. PNG неправильного размера 3×2 запрещает вычисление diff и отключает выгрузки.
5. Устанавливается viewport 390×844; страница не должна выходить за горизонтальную область. Проверяются ошибки страницы.

Скриншоты \`workbench-desktop.png\`, \`workbench-mobile.png\` сохраняются **только во временную папку** ОС: \`$TMPDIR/impulse-apple-kit-qa\` (или папку из переменной \`APPLE_QA_OUTPUT\`). В GitHub они не загружаются. Для визуальной приёмки владелец/reviewer должен открыть скриншоты, а не полагаться только на численный smoke.

**Ограничение:** этот README описывает команды, но не является доказательством их успешного выполнения на машине пользователя. Фактический browser-result требуется приложить к PR отдельно.

## Шаг 3 — измерение официального источника

[Реестр 26 кейсов](source-acceptance-matrix.csv) содержит ссылку на рекомендации Apple, необходимую вариативность и приоритет. Значения \`SOURCE_NOT_INSPECTED\`, \`source_measured=false\` и \`pixel_verified_*=false\` честно отражают текущее положение: измерения официальных Figma/Sketch UI Kits ещё не выполнены.

Чтобы изменить статус одного кейса:

1. Открыть [Apple Design Resources](https://developer.apple.com/design/resources/) и скачать официальные UI Kits **iOS/iPadOS 27 / macOS 27** согласно лицензии. Выбрать точный фрейм, компонент, вариант, тему и version.
2. Снять размеры: frame, inner padding, baseline, radius, blur/shadow, border, цвет, контраст; не заменять измерения «типичными числами Apple».
3. Сравнить разрешённый экспорт со скриншотом того же состояния Impulse (DPR, zoom, locale, data, fonts, viewport совпадают).
4. Провести отдельный interaction/keyboard/a11y тест с настоящими handlers, API, RBAC и серверными ошибками.
5. Независимый reviewer принимает конкретную ревизию. Изменение CSV без этих доказательств не является приёмкой.

## Результат для интегратора

Уровни готовности не смешивать: **материал присутствует** ≠ **оформлен тестом** ≠ **проверено в Chromium** ≠ **измерено по оригиналу Apple** ≠ **подтверждено reviewer** ≠ **допущено в main/production**.
